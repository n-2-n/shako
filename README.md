# shakonuko.com — статическая HTML-версия

Переписанный с нуля статический сайт психоаналитического психотерапевта
Ларисы Тольбиевны Шакануковой. Контент взят с shakonuko.com, вёрстка,
дизайн и разметка сделаны заново, без WordPress.

## Структура

```
index.html             Главная: герой, метод, цитата, форматы, FAQ, блог, CTA
about.html             Обо мне: биография, галерея, образование, опыт, публикации, запросы
services.html          Услуги и цены + правила совместной работы (#rules)
contacts.html          Форма заявки и прямые контакты
privacy.html           Политика обработки персональных данных (152-ФЗ)
404.html               Страница «не найдено» (ссылки от корня сайта)
blog/index.html        Список статей (собирается автоматически)
blog/*.html            Статьи — обычный HTML, по файлу на статью
partials/              Общие части: head.html, header.html, footer.html
tools/build.py         Сборка: вставляет общие части, списки статей, sitemap
robots.txt             Индексация + Clean-param для Яндекса
sitemap.xml            Карта сайта (собирается автоматически)
.htaccess              Кеш, сжатие, https/без-www, 404, заголовки безопасности
assets/css/style.css   Вся стилистика (дизайн-токены в :root)
assets/js/main.js      Меню, аккордеон, появление блоков, анти-спам формы
assets/img/            Логотип, иконка для iPhone, фотографии, og-image
```

## Как открыть

Сайт нужно смотреть через веб-сервер, а не двойным щелчком по файлу: ссылки
ведут на каталоги (`./`, `blog/`), и без сервера браузер покажет список файлов.

```bash
python3 -m http.server 4321
```

## Сборка

Шапка, подвал, общие теги в `<head>`, список статей, соседние статьи,
микроразметка статей и `sitemap.xml` собираются скриптом. Правка меню или
подвала делается один раз в `partials/`, затем:

```bash
python3 tools/build.py
```

Скрипт меняет только участки между маркерами `<!-- build:имя -->` и
`<!-- /build:имя -->`. Всё остальное в страницах — обычный HTML, его можно
править руками. Внутри маркеров руками не правьте: при следующей сборке
изменения затрутся.

Проверить, что всё собрано (удобно перед выкладкой):

```bash
python3 tools/build.py --check
```

Новая страница добавляется в словарь `PAGES` в начале `tools/build.py`,
пункт меню — в список `NAV`.

## Дизайн

* Фирменный логотип в шапке, подвале и в качестве фавикона (`assets/img/logo.svg`).
* Палитра построена вокруг цветов логотипа: тёплый бумажный фон, индиго-фиолетовый
  акцент, глубокий индиго для CTA-полосы. Все цвета — токены в `:root`.
* Типографика: только системные шрифты, ничего не загружается. Заголовки — Georgia
  (на Android — Noto Serif), текст — шрифт системы: San Francisco, Segoe UI или Roboto.
  Цены и цифры набраны основным шрифтом: в Georgia цифры «старого стиля» и прыгают по высоте.
* Убраны WordPress, счётчик Метрики, дублирующиеся меню и подвалы, пустые блоки.

## Мобильная версия

* **Выезжающая панель меню** справа: затемнение фона, блокировка прокрутки
  под панелью, закрытие по фону, по Escape и по выбору пункта, ловушка фокуса
  внутри панели, автозакрытие при возврате к десктопной ширине.
* **Нижняя панель действий** — WhatsApp, Telegram и «Записаться» всегда под большим
  пальцем; учитывает `env(safe-area-inset-bottom)` на iPhone с «чёлкой».
* Цели нажатия не меньше 48–52 px, `touch-action: manipulation`,
  убрана серая подсветка тапа.
* Поля формы — минимум 16 px, иначе iOS зумит страницу при фокусе.
* Ховер-эффекты отключены на сенсорных экранах (`@media (hover: none)`),
  чтобы карточки не «залипали» после касания.
* Нет горизонтальной прокрутки; якоря не прячутся под липкой шапкой
  (`scroll-margin-top`); анимации отключаются при `prefers-reduced-motion`.
* Шапка на узких экранах — одна строка: логотип, имя, бургер.
* Фото отдаются в WebP с запасным PNG: 489 КБ → 33 КБ и 346 КБ → 18 КБ.

## Блог

Статьи лежат в `blog/` — по одному обычному HTML-файлу на статью. Список
на странице блога, блок «Заметки о практике» на главной, переходы между
статьями, время чтения, дата и микроразметка `BlogPosting` собираются сами.

Как добавить статью:

1. Скопируйте любой файл из `blog/` и дайте ему имя латиницей,
   например `trevoga-i-kontrol.html`. Имя файла станет адресом статьи.
2. В `<head>` поменяйте `<title>`, `description`, `canonical`, og- и twitter-теги,
   а также даты:
   ```html
   <meta property="article:published_time" content="2026-10-01T10:00:00">
   <meta property="article:modified_time" content="2026-10-01T10:00:00">
   ```
3. Внутри `<article class="article">` замените `<h1>`, `<p class="article__lead">`
   (подводка — она же попадёт в список статей) и текст. Доступные блоки:
   `<p>`, `<h2>`, `<blockquote class="pull">` (акцентная цитата),
   `<dl class="terms">` (термин + пояснение).
4. Запустите `python3 tools/build.py`.

Статьи упорядочены по дате публикации. Даты четырёх перенесённых статей взяты
из WordPress как есть. Три из них опубликованы 5 мая 2025 года с разницей
в секунды, поэтому «Механизмы психической защиты» формально раньше, чем
«Психологические защиты», хотя по тексту это продолжение. Если важен порядок
чтения, поправьте `article:published_time` у одной из них.

## SEO

Сделано:

* Уникальные `<title>`, `description` и `canonical` на каждой странице;
  внутренние ссылки ведут на канонические адреса (`./`, `blog/`), без `index.html`.
* Open Graph + Twitter Card со сгенерированной картинкой `assets/img/og-image.jpg` (1200×630).
* Микроразметка Schema.org (JSON-LD): `Person`, `ProfessionalService`,
  `OfferCatalog` с ценами всех услуг, `FAQPage`, `BlogPosting` с датами,
  `BreadcrumbList`, `ContactPage`, `WebSite`. Google с 2026 года не показывает
  FAQ-сниппеты, поэтому `FAQPage` оставлен для полноты, а не ради выдачи.
* `robots.txt` с `Clean-param` (склейка utm/yclid в Яндексе) и ссылкой на `sitemap.xml`.
* Семантика: один `h1` на страницу, логичная иерархия заголовков, `lang="ru"`,
  осмысленные `alt`, ширина/высота у картинок (нет сдвигов макета), `font-display: swap`.
* Контент виден и без JavaScript: анимация появления включается, только когда
  скрипт в `<head>` поставил класс `js`.
* `.htaccess`: 301 на https и без www, кеш статики на год, gzip, заголовки безопасности.

Осталось сделать вам:

1. **Проверить адреса.** Canonical и sitemap ведут на `/about.html`, `/services.html`,
   `/contacts.html`. Если сохраняете старые адреса WordPress (`/about-me/`, `/servicies/`,
   `/contacts/`) — поправьте их в `<link rel="canonical">`, `sitemap.xml` и JSON-LD,
   либо настройте 301-редиректы со старых адресов на новые. Без этого можно потерять позиции.
2. **Подтвердить сайт** в Яндекс.Вебмастере и Google Search Console, загрузить sitemap.
3. **Вернуть счётчик** Яндекс.Метрики / Google Analytics, если он нужен (я его убрал).
4. **Заполнить адрес кабинета** в JSON-LD (`address`, `geo`) — это заметно помогает
   локальному поиску «психотерапевт рядом». Сейчас указаны только город и страна.
5. **Блог** — самый сильный источник трафика для такой практики. Четыре статьи уже
   перенесены в `blog/` с разметкой `BlogPosting`. Чем чаще выходят новые тексты,
   тем лучше; старые статьи стоит дополнять и обновлять.

## Защита формы обратной связи от спама

Форма на `contacts.html` сейчас не отправляет данные на сервер — она собирает письмо
и открывает почтовый клиент (`mailto:`). Это само по себе защищает от ботов: отправлять
нечего. Но как только появится настоящий обработчик, защита понадобится.

Уже встроено в `assets/js/main.js` (работает и с любым бэкендом):

* **Honeypot** — скрытое поле `website`. Человек его не видит, бот заполняет → отправка отменяется.
* **Тайм-трап** — форма, отправленная быстрее чем за 4 секунды после загрузки, отклоняется.
* **Валидация** — минимальные длины имени, контакта и сообщения, лимит 4000 знаков.
* **Эвристика** — сообщения с двумя и более ссылками или без кириллицы отклоняются.

Что добавить на сервере (клиентские проверки бот может обойти):

1. **Капча-невидимка.** Для российской аудитории — Яндекс SmartCaptcha (бесплатный тариф,
   работает без VPN). Альтернативы: Cloudflare Turnstile (бесплатно, без выбора
   светофоров), hCaptcha. reCAPTCHA в РФ работает нестабильно.
2. **Rate limit** — не более 3–5 отправок с одного IP в час.
3. **Серверная проверка honeypot и времени** — дублировать клиентские правила.
4. **Подпись формы** — одноразовый токен (nonce) с коротким сроком жизни,
   чтобы форму нельзя было постить напрямую скриптом.
5. **SPF, DKIM и DMARC** на домене — иначе письма с формы будут попадать в спам уже у вас.
6. **Не публиковать почту открытым текстом** — сейчас `larisa2710@list.ru` стоит в ссылках
   `mailto:`, её собирают парсеры. Можно оставить только мессенджеры и форму.

## Сервисы для обратной связи

Нужен только приём заявок, без своего бэкенда:

| Сервис | Бесплатно | Особенности |
|---|---|---|
| **Web3Forms** | 250 писем/мес | Только `action` в форме, ничего не хранит, есть honeypot и капча |
| **Formspree** | 50 заявок/мес | Хранит заявки, антиспам, уведомления на почту |
| **FormSubmit** | без лимита | Самый простой: `action="https://formsubmit.co/ваша@почта"` |
| **Getform / Basin** | 50–100/мес | Хранилище заявок, интеграции с Telegram и Slack |
| **Netlify Forms** | 100/мес | Если хостить сайт на Netlify — включается одной строкой |
| **Cloudflare Pages + Functions** | щедрый бесплатный лимит | Свой обработчик на 20 строк + Turnstile в комплекте |

Российские сервисы (удобны, если важны 152-ФЗ и оплата в рублях):

* **Яндекс Формы** — отдельная форма-страница или iframe, заявки падают в почту и в таблицу.
* **Битрикс24** — CRM-форма прямо на сайте, заявка сразу становится лидом, есть бесплатный тариф.
* **amoCRM** — то же самое, если нужна воронка и напоминания о записи.
* **Envybox / Callibri** — виджеты обратного звонка и чат, заточены под заявки.

Для записи на сессии может быть удобнее не форма, а календарь: **Calendly**,
**YCLIENTS** или **Яндекс.Услуги** — клиент сразу видит свободные слоты.

Отдельно: **Telegram-бот** как приёмник заявок — форма шлёт сообщение через Bot API,
заявки приходят в личку. Бесплатно, мгновенно и без хранения персональных данных на чужом сервере.

## Персональные данные (152-ФЗ)

Сделано:

* Страница [privacy.html](privacy.html) — политика в отношении обработки персональных
  данных: оператор, состав данных, цели, правовые основания, сроки хранения,
  права субъекта и порядок отзыва согласия.
* Обязательный чекбокс согласия в форме на `contacts.html` со ссылкой на политику.
  Без отметки форма не отправляется — проверка в `assets/js/main.js`.
* В тело письма автоматически добавляется строка с датой, временем и адресом страницы,
  где дано согласие. Это ваше подтверждение факта согласия — письма с заявками
  имеет смысл хранить, не удаляя эту строку.
* Ссылка на политику в подвале всех страниц; страница добавлена в `sitemap.xml`.

**Нужно заполнить перед публикацией.** В тексте политики места, требующие ваших
реквизитов, подсвечены жёлтым и помечены как `[уточнить]`:

1. Правовой статус — самозанятая, ИП или физическое лицо.
2. ИНН.
3. Адрес для направления корреспонденции (можно указать адрес кабинета или
   адрес для почтовых отправлений).
4. Сроки хранения данных — в тексте стоят рекомендуемые значения (1 год для обращений,
   3 года после завершения работы). Поставьте те, которых будете придерживаться на деле.

Найти их можно поиском по слову `[уточнить]` в `privacy.html`.

**Что учесть дополнительно:**

* Если вы обрабатываете данные как ИП или самозанятая систематически, Роскомнадзор
  требует подать **уведомление об обработке персональных данных** (через портал
  госуслуг или сайт РКН). Исключения из ст. 22 152-ФЗ к сайту с формой заявок
  обычно не применяются — уточните у юриста применительно к вашему статусу.
* При выборе зарубежного сервиса форм (Formspree, Getform и подобных) данные окажутся
  на серверах за пределами РФ. Для соблюдения требования о локализации (ч. 5 ст. 18
  152-ФЗ) первичная запись данных должна происходить в России — безопаснее
  Яндекс Формы, Битрикс24 или Telegram-бот на российском хостинге.
* Если вернёте Яндекс.Метрику, понадобится уведомление об использовании cookie
  и правка раздела 2 политики — сейчас там написано, что счётчиков нет.
* Политика — рабочий шаблон, а не юридическое заключение. Перед публикацией
  имеет смысл показать её юристу, особенно раздел о сроках хранения.

## Прочее

* **Шрифты** системные: Google Fonts не используются, поэтому сайт не зависит
  от чужих серверов и не передаёт IP посетителей за рубеж. Сменить шрифты можно
  в двух переменных `--font-display` и `--font-sans` в начале `style.css`.
* **Фотографии** взяты с действующего сайта и пересохранены в WebP; исходные PNG
  оставлены как запасной вариант для старых браузеров.
* **og-картинка** (`assets/img/og-image.jpg`) собрана из портрета и фирменных цветов —
  именно её увидят в превью ссылки в мессенджерах и соцсетях.
